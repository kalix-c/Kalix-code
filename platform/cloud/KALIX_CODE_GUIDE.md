# Kalix Code — دليل التشغيل والإدارة

## الوصول إلى الإنتاج

عنوان Kalix Code المنشور هو: **https://kalixcode-lvx9ubmm.manus.space**. صفحة البداية عامة، بينما تبقى مساحات المزوّدات والمستودعات محمية بتسجيل الدخول. بعد الدخول، لا يرى المستخدم إلا مزوّداته واتصال GitHub الخاص به.

## ربط GitHub

من **مساحة العمل ← المستودعات** اختر **ربط GitHub** وأدخل رمز وصول شخصيًا دقيق الصلاحيات. يتحقق Kalix من هوية الرمز لدى GitHub ثم يحفظ الرمز بصورة مشفرة على الخادم ضمن حساب المستخدم فقط. لا يعيد Kalix قيمة الرمز إلى الواجهة بعد الحفظ، ويمكن فصل الاتصال لإزالة بياناته المخزنة.

للتصفح فقط، أنشئ رمزًا يمنح وصول القراءة إلى محتوى المستودعات التي تريد رؤيتها. ولتحرير ملف، امنح الرمز وصول **Contents: Read and write** لتلك المستودعات فقط. يؤدي تعديل ملفات داخل `.github/workflows` إلى الحاجة إلى صلاحية workflows إضافية بحسب GitHub.[1]

## العمل مع المستودعات

تعرض Kalix المستودعات التي يصل إليها رمزك، وتوفر بحثًا محليًا بالاسم والوصف واللغة، ثم تتيح اختيار فرع واستعراض مجلداته وفتح ملفات نصية للتحرير. تدعم واجهة GitHub محتوى المجلدات والملفات عبر واجهة Contents API، والتي تُرجع محتويات المجلد أو الملف المحدد بحسب المسار والفرع.[2]

عند تعديل ملف، يطلب Kalix رسالة commit واضحة، ويعرض نافذة تأكيد تتضمن المستودع والفرع والمسار قبل التنفيذ. يتطلب التحديث نسخة `SHA` الحالية للملف؛ فإذا تغيّر الملف على GitHub تظهر رسالة تعارض ويجب تحديث المحتوى قبل إعادة المحاولة. يعتمد ذلك على سلوك GitHub الرسمي عند إنشاء أو تحديث محتوى ملف.[3]

> لا يرسل Kalix أي تعديل إلى GitHub ما لم تؤكد عملية **إنشاء commit** صراحةً. ولا يدعم في هذا الإصدار حذف الملفات أو إنشاء المستودعات أو عمليات merge التلقائية.

## إدارة مزوّدي النماذج

من **المزوّدات**، أدخل الاسم المعروض و`Base URL` ومفتاح API. يحاول Kalix اكتشاف النماذج عن طريق واجهة متوافقة مع OpenAI في المسار `/models`. إن لم ينجح الاكتشاف، يبقى المزوّد محفوظًا ويمكن إضافة النماذج يدويًا. مفاتيح المزوّدات مشفرة على الخادم ولا تظهر ثانية في المتصفح.

يوفر قسم **بحث وفلترة النماذج** التصفية حسب المزوّد، مصدر النموذج (مكتشف أو يدوي)، وتصنيف الإتاحة (مجاني أو مدفوع أو غير مصنف). لا يخمّن Kalix نوع تسعير نموذج مكتشف؛ يحدده صاحب الحساب بنفسه من القائمة بجانب النموذج أو عند إضافة نموذج يدوي.

## ضوابط وحدود الأمن

| المجال | الضابط المطبق | الحد العملي |
|---|---|---|
| الوصول | إجراءات الخادم مقيدة بهوية المستخدم المسجّل | يلزم تسجيل الدخول لإدارة المزوّدات أو GitHub |
| الأسرار | تشفير خادمي لمفاتيح المزوّدات ورموز GitHub، مع استجابات لا تحتويها | لا تشارك الرموز في لقطات الشاشة أو رسائل commit |
| مزوّدات النماذج | HTTPS فقط وحجب عناوين loopback والخاصة والمحجوزة | مخصّص لواجهات OpenAI-compatible في هذا الإصدار |
| GitHub | تحقق من الرمز قبل حفظه وحدود مسار/فرع/حجم ملف وتأكيد قبل الكتابة | يستعرض Kalix أول 100 مستودع متاح للرمز، ولا يحرر الملفات الأكبر من 750 KB |
| التعارضات | استخدام SHA للمحتوى الحالي عند الكتابة | حدّث الملف وأعد المراجعة عند ظهور تعارض |

تدعم GitHub REST API معلمات pagination حتى 100 عنصر لكل صفحة، ولذلك يعرض الإصدار الحالي أول 100 مستودع مرتبة وفق النشاط.[4]

## اختبار النسخة

تحققت النسخة الحالية من خمس مجموعات اختبارات، تضم **15 اختبارًا** لتسجيل الخروج، وتشفير وفلاتر المزوّدات، وعزل المسارات، وتعتيم رمز GitHub، وحماية مسارات الملفات، وكتابة محتوى Base64 مع مراجعة SHA. كما نجح فحص TypeScript وبناء الإنتاج، وتمت معاينة واجهات الحاسوب والهاتف.

## ملاحظات مستقبلية مقترحة

يمكن إضافة OAuth رسمي لـ GitHub لتفادي إدخال رمز يدوي، وتجزئة قائمة المستودعات لأكثر من 100 مستودع، وعرض pull requests أو تفريعات عمل منفصلة. يجب أن تبقى جميع العمليات المؤثرة على المستودع خلف خطوة تأكيد صريحة مشابهة لعملية إنشاء commit الحالية.
