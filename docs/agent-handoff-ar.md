# تسليم تطوير Kalix Code

## الحالة الحالية

مستودع Kalix Code العام هو `https://github.com/kalix-c/Kalix-code`، والفرع الرئيسي هو `master`. آخر أساس مرفوع يعرّف سياسة توزيع مستقلة باسم Kalix، ويحافظ مؤقتًا على أسماء الحزم الداخلية الموروثة لضمان عدم كسر منطق التشغيل.

## قرار التوزيع

المسار المعتمد طويل الأجل هو غلاف npm عام باسم `@kalix-code/kalix` مع أمر تنفيذي `kalix`، ووقت تشغيل محلي مستقل مضمّن داخل artifact، بدل مطالبة المستخدم باستنساخ المستودع أو تثبيت مساحة العمل الكاملة. يجب عدم نشر الأمر للمستخدم على أنه جاهز قبل نجاح الاختبارات التالية:

1. `npm pack --dry-run` ومراجعة محتويات الحزمة.
2. تثبيت tarball في مجلد مستهلك فارغ.
3. تشغيل `kalix --version` و`kalix --help`.
4. تشغيل `kalix web` من منزل مستخدم فارغ والتحقق من استجابة HTTP على localhost.
5. اختبار منفصل على Linux x64، ثم بناء artifact مناسب لـ Android/Termux arm64؛ لا يجوز استخدام artifact Linux x64 على Termux كبديل عن بناء منصة الهاتف.

## ما تم التحقق منه

تثبيت غلاف npm محليًا وتشغيل أوامر الإصدار والمساعدة نجحا. كما نجح بناء artifact أولي بلا روابط مطلقة إلى مسار المطور، مع تضمين واجهة `dist` المبنية. لكن اختبار إقلاع الويب من المستهلك النظيف ظل غير مكتمل في آخر دورة؛ ظهر أولًا اعتماد Sharp الأصلي، ثم عولج تحميله ليصبح مؤجلًا واختياريًا، وبعدها يجب إعادة بناء حزم الواجهة والعزل والعمليات قبل إعادة اختبار الإقلاع من جديد.

## القيود المهمة

لا يُنصح بإعادة تسمية جميع `@deepseek-ai/*` دفعة واحدة. يجب استخدام انتقال مرحلي: تبقى الأسماء الداخلية الحالية كطبقة توافق، بينما تظهر هوية Kalix في الحزمة العامة، والواجهة، والأوامر، والوثائق. كما أن حزمة npm العامة لا تلغي الحاجة إلى artifact خاص بالمنصة؛ Android/Termux يحتاجان توافقًا مع arm64 وتجنب NDK وCMake والاعتمادات الأصلية غير المتاحة.

يجب عدم وضع `NPM_TOKEN` في Git أو في ملفات `.npmrc` الملتزمة. الرمز الذي أُرسل في المحادثة ينبغي تدويره بعد انتهاء النشر. لا تُنفَّذ عملية `npm publish` إلا بعد مراجعة manifest والنسخة والـ scope ونجاح تثبيت tarball، ثم التحقق من `npm view` وتثبيت الحزمة المنشورة فعليًا.

## واجهة الويب المطلوبة بعد تثبيت الإصدار

الموقع الدائم الحالي هو `https://kalixcode-lvx9ubmm.manus.space`، ومشروع WebDev المنفصل موجود في `/home/ubuntu/kalix-code-cloud`. المطلوب التالي هو تحديث الواجهة العربية RTL لتستخدم هوية Kalix Code موحدة، واستبدال اللوحة الزرقاء بواجهة سوداء وفحمية مريحة للعين مع تباين نص واضح، وتحسين التجاوب للهاتف والحاسوب، ثم مراجعة مسارات المزودات والنماذج وGitHub والتشغيل المحلي.

يجب الاستفادة من المكونات الموجودة في المشروع بدل إعادة بنائها بلا داعٍ، وتغطية تغييرات الواجهة باختبارات Vitest، ثم فحص سطح المكتب والهاتف بصريًا قبل checkpoint. الأصول البصرية يجب أن تُرفع إلى تخزين WebDev المخصص، ولا تُحفظ كملفات كبيرة داخل مجلد المشروع.

## أوامر التحقق المقترحة

```bash
cd /home/ubuntu/Kalix-code
pnpm check
pnpm test
node --import tsx/esm scripts/release/pack-kalix-standalone.ts --out /tmp/kalix-standalone
cd /tmp/kalix-standalone/package
npm pack --dry-run
```

بعد اكتمال الإقلاع المحلي فقط يمكن تجهيز تعليمات المستخدم. لا تُرسل `npm install -g @kalix-code/kalix` على أنه يعمل قبل نشر نسخة ناجحة والتحقق منها من registry.

## معيار التسليم للوكيل التالي

يُعد العمل جاهزًا للمرحلة التالية عندما يمر artifact بتثبيت مستهلك نظيف وإقلاع HTTP محلي، ويُوثَّق دعم Linux وAndroid بصدق، وتُحدّث واجهة الويب السوداء المتجاوبة وتختبر، ثم تُرفع التغييرات إلى `master` في commits صغيرة قابلة للمراجعة.

> لا تُخفِ فشل اختبار أو قيدًا منصيًا بهدف تقديم أمر تثبيت مختصر؛ التوافق الصادق أهم من اختصار الأمر.
