## الهدف

أكمل إصدار Kalix Code طويل الأجل بطريقة صادقة: غلاف npm عام باسم `@kalix-code/kalix` وأمر `kalix`، مع وقت تشغيل محلي مستقل لا يطلب `git clone` أو `pnpm install` من المستخدم، ثم حدّث واجهة الويب العربية RTL وهوية Kalix Code ولوحة الألوان إلى أسود وفحمي مريح للعين ومتجاوب للهاتف والحاسوب.

## الحالة المهمة

آخر commit مرفوع هو `c9208b4e8d`، وقبله `d95e7997cd`. تم توثيق قرار فصل غلاف npm العام عن الحزم الداخلية. لا تعِد تسمية `@deepseek-ai/*` دفعة واحدة؛ أبقِها طبقة توافق داخلية مؤقتًا، وأظهر اسم Kalix في الحزمة العامة والواجهة والوثائق.

تم اختبار غلاف npm محليًا: `kalix --version` و`kalix --help` يعملان من مستهلك نظيف. تم بناء artifact يقارب 25MB مضغوطًا و212MB بعد فك الضغط، مع إزالة روابط المسار المطلق ومتجر pnpm وتضمين `apps/web/dist`. لكن اختبار `kalix web` من مستهلك نظيف فشل آخر مرة أثناء إقلاع الويب؛ يجب حفظ السجل الكامل وعدم اعتبار الإصدار جاهزًا حتى ينجح طلب HTTP فعلي من localhost في منزل مستخدم فارغ.

كان Sharp يمنع الإقلاع لأنه اعتماد أصلي، لذلك أُضيف تحميل ديناميكي واختياري له في حزم المرفقات، وأُعيد بناء حزمة المرفقات. تحقق أيضًا من أن `apps/web/dist` يدخل artifact؛ فقد كان سببًا سابقًا لرسالة `frontend dist not built`.

## طريقة العمل الإلزامية

ابدأ بـ `git status --short` و`git log -1 --oneline`. لا تستخدم `git reset --hard` ولا تعرض أي قيمة من `NPM_TOKEN`. لا تنفّذ `npm publish` قبل نجاح `npm pack --dry-run`، وتثبيت tarball في مجلد نظيف، وتشغيل `kalix --version` و`kalix --help` و`kalix web` مع فحص HTTP. اختبر Linux x64 منفصلًا، ولا تدّعِ أن artifact x64 يدعم Android/Termux arm64؛ أنشئ artifact خاصًا بالهاتف أو وثّق بوضوح أنه لم يُبنَ بعد.

شغّل `pnpm check` والاختبارات المركزة المناسبة. لا تخفِ أي فشل متعلق بـ Sharp أو node-pty أو Koffi أو الأصول المبنية. إذا احتاج الإصلاح تعديل مصدر TypeScript، أعد بناء الحزمة الرسمية ولا تعدّل `lib` يدويًا إلا كحل مؤقت موثق. حافظ على `node-pty` وKoffi والاعتمادات الأصلية الخاصة بـ Windows اختيارية ومؤجلة بحيث لا تمنع بدء Termux، مع إبقاء دعم Windows قابلًا للتثبيت.
